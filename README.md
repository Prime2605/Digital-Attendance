## ✨ Key Features

### 👔 Staff Dashboard
- **Period Controls:** Automatic detection of the current period; OTP generation is locked during breaks.
- **Secure OTP Generator:** Instantly generates a 6-digit OTP code valid for **30 seconds** with an interactive countdown timer.
- **Real-Time Attendance Monitoring:** Real-time stream of student registrations with student names, years, and period indicators.
- **Live Statistics Cards:** Displays today's attendance count, total enrolled students, and unique periods conducted today.
- **Export Reports:** Filter attendance records by date range and department, then export directly as a CSV file.

### 👨‍🎓 Student Dashboard
- **Instant Check-in:** Enter the secure OTP code generated by the staff to mark attendance for the current period.
- **Daily View Stats:**
  - **Periods Present Today:** Count of periods attended.
  - **Periods Remaining Today:** Count of periods left in the day (out of 8).
  - **Today's Attendance Rate:** Calculated percentage for completed periods only.
  - **Total Periods Today:** Reference of 8 periods per day.
- **Semester View Stats (4-Month Rolling):**
  - **Total Periods Attended:** Total present counts in the last 4 months (120 days).
  - **Total Periods Missed:** Auto-calculated based on working days.
  - **Working Days Tracked:** Total days in the 4-month window (excluding Sundays).
  - **Semester Attendance Rate:** Progress bar and status colored badge based on rate:
    - 🟢 **Excellent** ($\ge 75\%$)
    - 🟠 **Warning** ($50\% - 74\%$)
    - 🔴 **Critical** ($< 50\%$)
- **Detailed History:** Chronological cards showing Date, Period, Staff Name/Department, Time, and Status.

## 🔒 Security Architecture

- **Database-Synced OTPs:** Instead of in-memory dictionaries, OTPs are stored in a central Supabase table, ensuring cross-server synchronization (e.g., generating on a local laptop and submitting on Vercel works seamlessly).
- **Time-restricted Expiry:** OTPs expire strictly 30 seconds after creation. Validation checks both UTC server time and local expiration database timestamps.
- **Single-Use OTPs:** Used OTPs are deleted from active cache immediately after successful check-in.
- **Duplicate Prevention:** Strict PostgreSQL unique indexing ensures a student can mark attendance only once per period per day.
- **Role-Based Access (RBAC):** Dashboards are protected with secure session checks preventing unauthorized URL traversal.

- **Gold-Black-Silver Theme:** Customized HSL/Hex color values (`--gold: #D4AF37`, `--black: #0A0A0A`, `--white: #FFFFFF`, `--silver: #C0C0C0`) create a high-contrast dark professional UI.

  - **Cursor Interaction:** Parallax effect where camera angles subtly follow cursor movement.

## 🚀 Quick Start & Installation

### 1. Clone & Set Up Project
```bash
git clone https://github.com/Prime2605/Digital-Attendance.git
cd "Smart Attandance"
```

### 2. Install Dependencies
```bash
pip install -r requirements.txt
```

### 3. Configure Credentials
Create a `.env` file in the root directory:
```env
SUPABASE_URL=https://your-project-id.supabase.co
SUPABASE_KEY=your-anon-public-key
SECRET_KEY=generate-a-secure-random-key-here
```
> **Tip:** You can generate a strong SECRET_KEY via:
> `python -c "import secrets; print(secrets.token_hex(32))"`

### 4. Execute Locally
```bash
python app.py
```
Open [http://localhost:5000](http://localhost:5000) in your browser.

## 🗄️ Database Setup & Migrations

Deploy the tables and seed data in your Supabase project. Go to **Supabase Dashboard** $\rightarrow$ **SQL Editor** $\rightarrow$ **New Query**, paste the code below, and click **Run**:

```sql
-- 1. Create Extensions
CREATE EXTENSION IF NOT EXISTS "uuid-ossp";

-- 2. Create Users Table
CREATE TABLE IF NOT EXISTS users (
    id UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
    name VARCHAR(255) NOT NULL,
    role VARCHAR(50) NOT NULL CHECK (role IN ('staff', 'student')),
    email VARCHAR(255) UNIQUE NOT NULL,
    password VARCHAR(255) NOT NULL,
    department VARCHAR(255),
    year VARCHAR(50),
    created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW()
);

-- 3. Create OTP Table
CREATE TABLE IF NOT EXISTS otp (
    id UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
    otp_code VARCHAR(6) NOT NULL,
    generated_by UUID REFERENCES users(id),
    staff_name TEXT,
    created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW(),
    expires_at TIMESTAMP WITH TIME ZONE NOT NULL
);

-- 4. Create Attendance Table
CREATE TABLE IF NOT EXISTS attendance (
    id UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
    student_id UUID REFERENCES users(id),
    date DATE NOT NULL,
    period INTEGER NOT NULL CHECK (period BETWEEN 1 AND 8),
    time TIME NOT NULL,
    status VARCHAR(50) DEFAULT 'present',
    staff_name TEXT,
    created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW(),
    CONSTRAINT unique_student_period_date UNIQUE (student_id, date, period)
);

-- 5. Create Performance Indexes
CREATE INDEX IF NOT EXISTS idx_users_email ON users(email);
CREATE INDEX IF NOT EXISTS idx_users_role ON users(role);
CREATE INDEX IF NOT EXISTS idx_otp_code ON otp(otp_code);
CREATE INDEX IF NOT EXISTS idx_attendance_student ON attendance(student_id);
CREATE INDEX IF NOT EXISTS idx_attendance_date ON attendance(date);
```

## ☁️ Production Deployment Guide

### Deploying to Vercel
1. Install Vercel CLI locally: `npm i -g vercel`
2. Run command `vercel` from the project directory.
3. Link to your GitHub repository and follow the prompts.
4. Input the environment variables in the Vercel project settings dashboard:
   - `SUPABASE_URL`
   - `SUPABASE_KEY`
   - `SECRET_KEY`
5. Vercel utilizes `vercel.json` to route Python requests to the `@vercel/python` builder. Push changes to `main` for automated continuous deployments.

### Deploying to Render
1. Push the project to GitHub.
2. Go to **Render Dashboard** $\rightarrow$ **New Web Service**.
3. Choose Python environment, and configure:
   - Build Command: `pip install -r requirements.txt`
   - Start Command: `gunicorn app:app`
4. Set the environment variables under the **Environment** tab.

## 🔧 Troubleshooting

### "getaddrinfo failed" or ConnectError
- **Cause:** Network unreachable or DNS resolution failure for the Supabase API.
- **Solution:** Verify that your system has internet access, and double-check `SUPABASE_URL` in the `.env` file.

### Student Login returns "Invalid credentials"
- **Cause:** Migrations were not seeded into the target database.
- **Solution:** Run the seed statements located in the [Database Setup](#-database-setup--migrations) section.

### Time shows incorrect hours on Vercel
- **Cause:** The Vercel function environment runs on UTC.
- **Solution:** Ensure `app.py` defines the timezone using `timezone(timedelta(hours=5, minutes=30))` (IST) and constructs native datetimes accordingly.
